Virtualizing Large Tables with TanStack Virtual

Learn how to improve the performance of large React tables by rendering only visible rows with TanStack Virtual, reducing DOM size, improving scrolling, and creating scalable data-heavy interfaces.

  • React
  • TanStack Virtual
  • Performance

Tables are one of the most common places where frontend performance problems become noticeable. Rendering a few dozen rows is usually not an issue, but displaying thousands of rows at the same time can create a large DOM tree, increase memory usage, and make scrolling feel slow. Instead of rendering every row, virtualization allows us to render only the rows currently visible inside the viewport.

What is table virtualization?

Table virtualization is a technique where only the visible rows of a large dataset are rendered to the DOM. As the user scrolls, the virtualized list removes rows that are no longer visible and renders the rows that have entered the viewport. The table can still represent thousands of records, but the browser only has to manage a small number of actual DOM elements at any moment.

This is especially useful for admin dashboards, analytics applications, CRM systems, reporting tools, and other interfaces where users need to work with large datasets.

TanStack Table and TanStack Virtual solve different problems

When building a large React table, it is useful to understand the difference between table management and virtualization. TanStack Table handles table functionality such as columns, sorting, filtering, pagination, and row models. TanStack Virtual handles efficient rendering by calculating which items should actually be displayed.

Using them together provides a flexible solution for building high-performance data tables. The table library manages the data and behavior, while the virtualization library controls how many rows are mounted in the DOM.

Install TanStack Virtual

Terminal
npm install @tanstack/react-virtual

The React Virtual package provides hooks that can calculate the visible range of items inside a scrollable container. We can then use that information to render only the rows that are currently needed.

Create a virtualized table

A basic virtualized table starts with a scrollable container. The virtualizer needs a reference to this element so it can monitor the scroll position and determine which rows should be rendered.

DataTable.jsx
"use client";

import { useRef } from "react";
import { useVirtualizer } from "@tanstack/react-virtual";

export default function DataTable({ data }) {
  const parentRef = useRef(null);

  const rowVirtualizer = useVirtualizer({
    count: data.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 50,
    overscan: 5,
  });

  return (
    <div
      ref={parentRef}
      style={{
        height: "600px",
        overflow: "auto",
      }}
    >
      <div
        style={{
          height: `${rowVirtualizer.getTotalSize()}px`,
          position: "relative",
        }}
      >
        {rowVirtualizer.getVirtualItems().map((virtualRow) => {
          const row = data[virtualRow.index];

          return (
            <div
              key={virtualRow.key}
              style={{
                position: "absolute",
                top: 0,
                left: 0,
                width: "100%",
                height: `${virtualRow.size}px`,
                transform: `translateY(${virtualRow.start}px)`,
              }}
            >
              {row.name}
            </div>
          );
        })}
      </div>
    </div>
  );
}

The important part of this implementation is that data.length can represent thousands of records, while getVirtualItems returns only the rows that need to be displayed. The inner container keeps the correct total height, which makes the scrollbar represent the full dataset even though most rows are not mounted.

Use overscan for smoother scrolling

The overscan option controls how many additional rows are rendered outside the visible area. Rendering a few extra rows helps prevent blank spaces from appearing when the user scrolls quickly because the next rows are already mounted before they enter the viewport.

virtualizer.js
const rowVirtualizer = useVirtualizer({
  count: data.length,
  getScrollElement: () => parentRef.current,
  estimateSize: () => 50,
  overscan: 10,
});

There is a trade-off when choosing the overscan value. A larger value can make fast scrolling smoother, but it also increases the number of DOM elements being rendered. For most tables, a small value such as 5 to 10 is a reasonable starting point.

Combine TanStack Table with TanStack Virtual

For a production data table, I usually recommend combining TanStack Table with TanStack Virtual. TanStack Table can manage sorting, filtering, and row models, while TanStack Virtual can efficiently render the resulting rows.

DataTable.jsx
const table = useReactTable({
  data,
  columns,
  getCoreRowModel: getCoreRowModel(),
  getSortedRowModel: getSortedRowModel(),
});

const rows = table.getRowModel().rows;

const rowVirtualizer = useVirtualizer({
  count: rows.length,
  getScrollElement: () => parentRef.current,
  estimateSize: () => 50,
  overscan: 5,
});

This approach keeps the table logic separate from the rendering strategy. Sorting and filtering can change the rows returned by TanStack Table, and the virtualizer automatically works with the updated row collection.

Be careful with dynamic row heights

Virtualization works best when row heights are predictable. If every row has the same height, estimateSize is straightforward and the virtualizer can calculate positions efficiently. However, tables with wrapped text, expandable content, or dynamically sized rows require more careful measurement.

virtualizer.js
const rowVirtualizer = useVirtualizer({
  count: rows.length,
  getScrollElement: () => parentRef.current,
  estimateSize: () => 50,
  measureElement: (element) => element?.getBoundingClientRect().height,
  overscan: 5,
});

When row sizes can change, measuring the rendered elements helps the virtualizer maintain more accurate positions. In practice, keeping table rows consistent whenever possible usually results in a simpler and more predictable implementation.

Virtualization is not a replacement for pagination

Virtualization and pagination solve different problems. Virtualization improves the rendering performance of data that is already available in the browser. Pagination limits how much data is loaded and processed in the first place.

If an API returns 100,000 records, virtualizing the table can reduce the DOM workload, but the browser still has to download and store all 100,000 records. For very large datasets, server-side pagination or infinite scrolling combined with virtualization is often a better architecture.

A practical architecture for large datasets

For a large production application, I would typically combine server-side filtering, sorting, and pagination with client-side virtualization. The server returns only the relevant records, while TanStack Virtual ensures that the current page or loaded dataset does not create an unnecessarily large DOM tree.

DataTable.jsx
const virtualRows = rowVirtualizer.getVirtualItems();

return (
  <div ref={parentRef} className="h-[600px] overflow-auto">
    <div
      style={{
        height: `${rowVirtualizer.getTotalSize()}px`,
        position: "relative",
      }}
    >
      {virtualRows.map((virtualRow) => {
        const row = rows[virtualRow.index];

        return (
          <div
            key={row.id}
            ref={rowVirtualizer.measureElement}
            data-index={virtualRow.index}
            className="absolute left-0 top-0 w-full"
            style={{
              transform: `translateY(${virtualRow.start}px)`,
            }}
          >
            {row.getVisibleCells().map((cell) => (
              <div key={cell.id}>
                {flexRender(
                  cell.column.columnDef.cell,
                  cell.getContext()
                )}
              </div>
            ))}
          </div>
        );
      })}
    </div>
  </div>
);

Measure performance before and after

The biggest benefit of virtualization becomes noticeable when a table contains hundreds or thousands of rows. However, it is still important to measure the actual performance of your application. Browser DevTools can help identify long rendering tasks, excessive DOM nodes, memory usage, and slow event handlers.

Virtualization is especially valuable when users experience slow initial rendering, laggy scrolling, or high memory consumption caused by large numbers of DOM elements. If the dataset is small, adding virtualization may introduce unnecessary complexity without providing a meaningful benefit.

Final thoughts

Large tables do not have to become a performance bottleneck. TanStack Virtual provides a practical way to render only the rows users can actually see, while maintaining the scrolling experience of a much larger dataset. When combined with TanStack Table, server-side pagination, and efficient data fetching, it becomes possible to build responsive data-heavy interfaces that can scale as the application grows.

The key is to choose the right optimization for the problem. Use virtualization when the DOM becomes too large, use pagination when the dataset itself is too large to load at once, and combine both techniques when building applications that need to handle significant amounts of data.
