Deploying Node.js and Next.js Applications with PM2 and Nginx

Learn how to deploy Node.js and Next.js applications on a Linux server using PM2 and Nginx, configure reverse proxying, enable automatic process restarts, and run production applications reliably.

  • PM2
  • Nginx
  • Deployment

Deploying a Node.js or Next.js application to a production server involves more than simply starting the application with npm run start. A production application needs a process manager to keep the application running, automatically restart it when necessary, and a web server to handle incoming requests efficiently. PM2 and Nginx are two popular tools that work well together for this purpose.

In this guide, we will deploy a Node.js or Next.js application on a Linux server using PM2 as the process manager and Nginx as a reverse proxy. We will also configure the application to run in production, connect it to a domain, and make sure it can restart automatically after a server reboot.

What is PM2?

PM2 is a production process manager for Node.js applications. Instead of running your application directly with node or npm, PM2 manages the application process and keeps it running in the background.

PM2 can automatically restart an application when it crashes, monitor application processes, manage logs, run applications in cluster mode, and restore processes after a server restart. This makes it useful for running Node.js and Next.js applications in production.

What is Nginx?

Nginx is a high performance web server and reverse proxy. In a typical Node.js deployment, the application runs on an internal port such as 3000, while Nginx listens for public HTTP and HTTPS requests.

When a user visits your domain, Nginx receives the request and forwards it to the Node.js or Next.js application running on the local server. This setup keeps the application server separate from the public facing web server and makes it easier to configure domains, SSL certificates, redirects, and other web server features.

The deployment architecture

The basic architecture is straightforward. The user sends a request to your domain, Nginx receives the request, and Nginx forwards it to the application managed by PM2. The application then processes the request and sends the response back through Nginx.

Architecture
User
  ↓
Nginx (Port 80 / 443)
  ↓
PM2
  ↓
Node.js / Next.js Application (Port 3000)

This architecture allows the Node.js application to run on a local port while Nginx handles public traffic. You do not need to expose the application port directly to the internet.

Prepare the server

Before deploying the application, you need a Linux server with Node.js, npm, Git, and Nginx installed. Ubuntu is a common choice for hosting Node.js applications.

First, update the server packages.

Terminal
sudo apt update && sudo apt upgrade -y

You can then install Node.js and npm using your preferred installation method. After installation, verify that Node.js and npm are available.

Terminal
node -v
npm -v

Install PM2

PM2 can be installed globally using npm. Installing it globally allows you to use the pm2 command from anywhere on the server.

Terminal
sudo npm install -g pm2

After installation, verify that PM2 is available.

Terminal
pm2 -v

Upload or clone your application

Once the server is ready, place your application inside a directory on the server. If your project is stored in Git, you can clone the repository directly.

Terminal
cd /var/www
sudo git clone YOUR_REPOSITORY_URL my-app
cd my-app

You can also upload the project files using tools such as SFTP or an FTP client, depending on your hosting environment. The important part is to make sure the application is located in a directory where your deployment user has the required permissions.

Install project dependencies

After moving into the project directory, install the application's dependencies.

Terminal
npm install

For production deployments, npm ci can also be used when the project contains a package-lock.json file. This installs the exact dependency versions defined in the lock file.

Terminal
npm ci

Build a Next.js application

Next.js applications should be built before starting them in production mode. The build process creates the optimized production output required by Next.js.

Terminal
npm run build

After the build completes successfully, the application can be started using the production start command.

Terminal
npm run start

By default, a Next.js application usually listens on port 3000. You can test the application directly from the server using curl.

Terminal
curl http://localhost:3000

Run the application with PM2

Instead of running npm run start directly, PM2 can manage the production application. For a Next.js application, PM2 can execute the npm start command.

Terminal
pm2 start npm --name 'my-next-app' -- start

The --name option gives the process a readable name. This makes it easier to identify and manage the application when multiple Node.js applications are running on the same server.

You can check all running PM2 processes with the following command.

Terminal
pm2 list

Manage the application with PM2

PM2 provides simple commands for managing your application. You can restart the application after deploying new code, stop it when necessary, and remove it from the PM2 process list.

Terminal
pm2 restart my-next-app
pm2 stop my-next-app
pm2 delete my-next-app

You can also view the application's output and error logs using the PM2 logs command.

Terminal
pm2 logs my-next-app

Configure PM2 to start after reboot

One of the main advantages of PM2 is that it can restore your applications after a server restart. First, generate the startup command for your system.

Terminal
pm2 startup

PM2 will display a command that should be executed with the required system permissions. Run that command and then save the currently running PM2 processes.

Terminal
pm2 save

After this configuration, PM2 can automatically restore the saved processes when the server starts again.

Install Nginx

Next, install Nginx on the server. Nginx will act as the reverse proxy between the public internet and your Node.js or Next.js application.

Terminal
sudo apt install nginx -y

After installation, check whether Nginx is running.

Terminal
sudo systemctl status nginx

If Nginx is not running, you can start it using systemctl.

Terminal
sudo systemctl start nginx

Configure Nginx as a reverse proxy

Create a new Nginx server configuration for your domain. On Ubuntu, site-specific configurations are commonly stored inside /etc/nginx/sites-available.

Terminal
sudo nano /etc/nginx/sites-available/my-next-app

Add a server block that forwards requests to the Next.js application running on port 3000.

my-next-app
server {
    listen 80;
    server_name example.com [www.example.com;

](http://www.example.com;

)    location / {
        proxy_pass [http://127.0.0.1:3000;
](http://127.0.0.1:3000;
)        proxy_http_version 1.1;

        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

The proxy_pass directive forwards requests to the application running on port 3000. The proxy headers preserve useful information about the original client request and are commonly used when running applications behind a reverse proxy.

Enable the Nginx site

After creating the configuration, create a symbolic link inside the sites-enabled directory.

Terminal
sudo ln -s /etc/nginx/sites-available/my-next-app /etc/nginx/sites-enabled/

Before restarting Nginx, always test the configuration for syntax errors.

Terminal
sudo nginx -t

If the configuration test is successful, reload Nginx to apply the changes.

Terminal
sudo systemctl reload nginx

Point your domain to the server

Your domain must point to the public IP address of the server. Create an A record for the domain and point it to your server's IP address.

DNS
Type: A
Name: @
Value: YOUR_SERVER_IP

Type: A
Name: www
Value: YOUR_SERVER_IP

DNS changes may take some time to propagate. Once the domain resolves to the server, Nginx should receive the request and forward it to the application managed by PM2.

Enable HTTPS with SSL

Running a production application over HTTPS is strongly recommended. One common approach on Ubuntu is to use Certbot with Nginx to obtain and configure a Let's Encrypt SSL certificate.

Terminal
sudo apt install certbot python3-certbot-nginx -y

After installing Certbot, request a certificate for your domain.

Terminal
sudo certbot --nginx -d example.com -d [www.example.com](http://www.example.com)

Certbot can update the Nginx configuration and configure HTTPS for the domain. It can also set up automatic certificate renewal so that the certificate does not expire without being renewed.

Use environment variables in production

Production applications commonly require environment variables for API URLs, database connections, authentication secrets, and other configuration values. These values should not be hardcoded directly into the application source code.

For a Next.js application, create the appropriate environment file on the server and make sure the required variables are available before running the production build.

.env.production
NEXT_PUBLIC_API_URL=https://api.example.com
DATABASE_URL=your_database_connection
AUTH_SECRET=your_secret

If an environment variable is required during the Next.js build process, make sure it is available before running npm run build. After changing environment variables that are included in the build output, you may need to rebuild the application.

Deploy updates to the application

When new code is pushed to the repository, the deployment process typically involves pulling the latest changes, installing any new dependencies, rebuilding the application, and restarting the PM2 process.

Terminal
cd /var/www/my-app

git pull origin main

npm ci

npm run build

pm2 restart my-next-app

For a simple deployment, these commands are often enough to update a running Next.js application. More advanced projects can automate this workflow using CI/CD pipelines so that deployments happen automatically after changes are merged.

Node.js applications use the same architecture

The same PM2 and Nginx architecture can be used for a regular Node.js application. The main difference is the command used to start the application.

Terminal
pm2 start server.js --name 'my-node-app'

If the Node.js application uses an npm start script, you can also start it through npm using PM2.

Terminal
pm2 start npm --name 'my-node-app' -- start

Nginx can then forward requests to the port where the Node.js server is listening, just as it does with a Next.js application.

Check logs when something goes wrong

When a production application is not working as expected, checking logs should be one of the first troubleshooting steps. PM2 provides access to application output and error logs.

Terminal
pm2 logs my-next-app

You can also inspect the Nginx error log when requests are not reaching the application correctly.

Terminal
sudo tail -f /var/log/nginx/error.log

If the application works at http://localhost:3000 but does not work through the domain, the problem is often related to Nginx configuration, DNS, firewall rules, or SSL configuration.

Common deployment checklist

Before considering the deployment complete, it is useful to verify each part of the stack.

Deployment Checklist
✓ Node.js is installed
✓ Application dependencies are installed
✓ Production build completes successfully
✓ Application runs correctly on localhost
✓ PM2 process is running
✓ PM2 startup configuration is enabled
✓ PM2 processes have been saved
✓ Nginx is running
✓ Nginx configuration passes nginx -t
✓ Domain DNS points to the server
✓ Nginx reverse proxy is configured
✓ HTTPS is enabled
✓ Production environment variables are configured

Final thoughts

Deploying a Node.js or Next.js application with PM2 and Nginx provides a practical foundation for running production applications on a Linux server. PM2 keeps the application process running and helps manage restarts and logs, while Nginx handles incoming web traffic and acts as a reverse proxy.

The basic workflow is straightforward: prepare the server, install dependencies, build the application, start it with PM2, configure Nginx as a reverse proxy, point the domain to the server, and enable HTTPS. Once this setup is in place, you have a reliable foundation that can be extended with automated deployments, monitoring, load balancing, and other production infrastructure.

For smaller projects, this setup is often enough to run a production application reliably. As the application grows, you can build on the same foundation by introducing CI/CD pipelines, containerization, centralized logging, monitoring, and scalable infrastructure.
